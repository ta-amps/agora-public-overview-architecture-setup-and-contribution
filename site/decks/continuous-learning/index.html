Post-training tuning and continuous learning

The system is designed to keep learning: we re-tune on demand.

Meta’s Muse Glimmer 30B is tuned on checked examples, and we promote a tuned model only after evaluation, under a rule fixed before scoring.

ta-amps · Post-training tuning and continuous learning · ta-amps · Agora, the overview · October 30, 20261

Speaker notes

This deck is about what happens after a model ships. Training made it, and then it froze: the tools, schemas and failures it meets afterwards never reach its weights. Here the system is designed to keep learning: we re-tune on demand and promote only after evaluation. Learners turn execution reports into memory, path statistics and routing advice, and Meta’s Muse Glimmer 30B is tuned on checked examples and kept only when it beats its base on a test it never saw, under a rule fixed before scoring. Every result in this deck comes from our evaluation tasks, and nothing has been promoted or admitted.

ta-amps · Post-training tuning and continuous learning · Why and how · the loop3

Speaker notes

Read the loop clockwise from the top left. Owned templates generate the examples, so no model writes a row or a label. Curation rejects repeats and anything that looks like a test row. The test set is frozen and recorded before any model sees it. A small adapter trains on top of the base, which never changes, and it stays a candidate. Evaluation scores the candidate, the current champion and the unchanged base on the same rows, and the promotion rule, written before any training, decides. The saved adapter must then reload onto a fresh copy of the base and reply exactly the same. Only then does the champion pointer move. Keeping the champion is a valid outcome, and because every version is kept, rolling back is moving the pointer back. The next round starts from the champion, with new examples aimed at its failures.

Pre-registration and frozen tests

FIXED BEFORE ANY SCORE

FROZEN TEST

150 rows over tool families that training never sees, recorded once and never changed.

FRESH TEST

New rows each round, recorded before any model sees them.

THE PROMOTION RULE

Committed before the first training round, and pinned by a test.

NO LOOK-ALIKES

Fingerprints reject training rows that match a test row, its request or its template.

Learners: memory, paths and routing

Not all learning changes a model. Learner runs are ordinary Tasks: they read execution reports and write their advice as versioned Task Objects.

MEMORY

Similar past work

Each run is fingerprinted. Before new work, recall finds similar past runs and how they went, failures included.

memory · minhash-lsh

PATHS

What succeeds

Runs are grouped by category, template, phrasing and shim into scorecards. They show associations, not causes.

path_statistics · wilson-grouping

ROUTING

Which way to try

Weights suggest a shim, method, harness or model, keep exploring the others, and move only with enough evidence.

routing_weights · beta-bandit

MODEL WEIGHTS

The third layer: tuning on real runs

It takes only opted-in, checked, rights-cleared runs.

Advice only: never a permission, never a hidden agent. The learners are implemented and tested; their measured results so far come from our evaluation tasks.

Speaker notes

Not all learning changes a model. Learners are ordinary Tasks that read execution reports and write versioned Task Objects. Memory fingerprints each run, so before new work an agent can recall similar past runs and how they went, failures included. Path statistics group runs into scorecards of what succeeds; they show associations, not causes. Routing weights suggest which shim, method, harness or model to try, keep exploring the alternatives, and move only with enough evidence. Their outputs are advice, never a permission. Changing model weights from real runs is the third layer: it takes only opted-in, checked, rights-cleared runs, and today’s tuning uses examples made from templates. The learners pass their tests on our evaluations.

  • Measured Memory, path-statistics and routing-weights learners: implemented and tested. Teleion Fabric’s execution-learning record. Local tests are not evidence that any learner improves real work; that needs the evaluations each learner names, on real permitted runs. Evidence
  • Measured Self-learning library search with Teleion Fabric's model shim shims, a local check: Recall@1 23.3% to 100.0% across 60 queries over 79 seed packs (MRR 0.341 to 1.000 in 1.0 round, 82.8% token reduction, 0.30 ms retrieval, 10 compiled shims at 0.026 ms, 10 of 10 independent reviews). An offline evaluation over the 79-pack library, with no model calls: each pack’s Task Objects enriched for search, an index across fields, reflection on misses, and an independent check (a self-approval was refused with a 409). Safety and rollback

A round that fails any check leaves the champion where it was.

FROZEN TESTS

Held-out tool families

Training never sees the test’s tools, and every test set is recorded once and never changed.

PRE-REGISTRATION

Recorded before scores

The rule and each fresh test are recorded before any model is scored on them.

CONTAMINATION CHECKS

No look-alikes

Fingerprints reject a training row that matches a test row, its request or its template.

RELOAD EQUIVALENCE

It must reload the same

The saved adapter, loaded onto a fresh copy of the base, must reproduce its replies exactly.

A RULE FIXED IN ADVANCE

Beat the base, break nothing

A gain whose lower bound is above zero, and no drop in valid output, refusals or general skills.

ROLLBACK

One pointer, every version kept

Adapters are never overwritten. Promotion moves one pointer, so rolling back moves it back.

Promotion changes no deployment, publication, admission or serving. Privacy is checked too: another key tried to read everything the earlier tuning rounds wrote, and all 303 reads were denied.

ta-amps · Post-training tuning and continuous learning · How it runs · safety and rollback8

Speaker notes

These rules keep the loop honest. Tests are frozen, held out by whole tool families and recorded once. The promotion rule and each fresh test are recorded before scoring. Fingerprints keep look-alikes of test rows out of training. A saved adapter must reload onto a fresh copy of the base and reply exactly the same. The rule asks for a real gain, with a lower bound above zero, and no drop in valid output, refusals or general skills. Because adapters are never overwritten and the champion is one pointer that keeps every version, rolling back is moving that pointer back. Promotion here changes no deployment, publication, admission or serving. Privacy is checked as well: after the earlier tuning rounds, a second key tried to read all 303 records, blob chunks and runs they wrote, and every read was denied.

  • Measured Another key tried to read everything the earlier tuning rounds wrote: all 303 reads were denied. A final sweep after one model’s tuning rounds: another principal tried to read 115 private records, 133 blob chunks and 55 execution runs. After a second model’s rounds, all 193 such reads were denied too. Evidence

Limits: what these results cover

  • Every result comes from our evaluations, one task per result: typed tool calls for Teleion Fabric’s own tools.
  • Each configuration ran once, with one seed, so nothing measures the spread between runs.
  • The 150-row tests are small: they can miss a real gain of a few points.
  • Rounds start on demand, on recorded runs and our evaluations.
  • Adapter weights stay private, and nothing has been promoted or admitted.
  • The learners pass their tests on our evaluations.

Every kept-out round and every failure stays on the record.

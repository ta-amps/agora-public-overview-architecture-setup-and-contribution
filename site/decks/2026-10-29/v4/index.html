Meta Global AI Developer Hackathon · Indie track

AI is smart.
The way we use it is frustratingly dumb.

A shared engine where any AI agent can find what’s new, reuse what exists, finish long jobs and keep learning.

ta-amps · github.com/ta-amps

Speaker notes

AI models are remarkably capable. But the way we use them wastes most of that: they don’t know what came out today, they rewrite code that already exists, and they need babysitting on long jobs. Training alone doesn’t fix any of it. This project is about using AI smartly.

Why AI work is frustratingly dumb

01

It doesn’t know what’s new, and neither do we

Hundreds of thousands of new repos, papers and tools appear every day. No model, and no person, can keep up.

02

It rewrites what already exists

A model is compressed knowledge, not a library of reusable code. So it writes non-novel code again and again.

03

It needs babysitting

It doesn’t break a big job into small, independent pieces in a graph that many workers can claim, check and finish.

ACROSS ALL THREE

Training doesn’t fix it

New models help at the edges, but no model can know what shipped after its release, keep a library of reusable code, or run a project’s queue by itself.

The problem

Speaker notes

Three problems. First, nobody can keep up: GitHub alone sees well over a hundred million new repositories a year, hundreds of thousands every day, plus a flood of papers and tools. Models can’t know what shipped after training, and people can’t read it all either. Second, a model is compressed knowledge, not a code library, so it regenerates code that already exists. Third, it doesn’t break a big job into small, independent pieces in a graph that many workers can claim, check and finish in parallel; harnesses help, but a single process trying to do everything still loses track. Underneath all three: training doesn’t fix it.

Why it keeps happening

Models aren’t trained to organize, reuse or learn from their own work.

Harnesses each try, in their own way. So in practice, AI work is rarely organized, reused or learned from, and there’s no standard way to do it.

The problem

Speaker notes

The model itself isn’t trained to organize, reuse or learn from what it produces. Some harnesses add pieces of that, each differently, so there’s a hodgepodge of partial solutions and no shared standard. That’s the gap we fill.

One answer, three parts

PART 1

Nouns and verbs

Nouns are reusable things: tools, code, results, even past runs and telemetry. Verbs are small jobs any agent can claim, execute and report.

PART 2

Shims

Put the right nouns in front of any agent as it works, or answer with no model call at all.

PART 3

Learning

Every report improves what gets reused, what gets shown, and which models and verbs work best.

Workers don’t just use nouns and verbs. They create both: new findings, and new follow-up jobs.

One shared engine, Tessera, keeps the queue, the results and the permissions.

The answer

Speaker notes

Three parts. Nouns and verbs give AI work a shared shape: reusable things, and small jobs that are claimed, executed and reported, including failures. Shims deliver the right nouns, including past runs and telemetry, to any agent without changing it. Learning means every report makes the next job better. And workers can create new verbs, not just nouns, which is how big jobs break down into smaller ones.

How it works

Speaker notes

Everything is one of four things. Nouns are reusable things, including the history and telemetry of past runs. Verbs are jobs: claim, execute, report. Surfaces are where people and agents come in. Infrastructure is the small shared engine. Workers can report back both new nouns and new verbs. Seed packs are just plain-language bundles of nouns and verbs, separate from any surface.

Eranos: spare AI tokens build tools for nonprofits

Your agent picks an open task and builds a small kit, like an intake checklist or a service finder. A different volunteer’s agent checks it before anyone can use it.

1 · CHECK

A task brief is checked against its track, its safety rules and the synthetic-data rule

2 · BUILD

One volunteer’s agent claims it, builds the kit and tests it on synthetic cases

3 · REVIEW

A different agent or a person reviews it. A builder can never approve its own kit

4 · PUBLISH

Only then does it enter the free catalog. Sensitive kits wait for a nonprofit steward

Kits, briefs, test cases and reviews are nouns. Checking, building and reviewing are verbs. People keep every interview and every decision about a person. Today: five example kits pass build, check and review on a laptop; all data is synthetic.

The answer, for good causes

Speaker notes

Eranos is where this matters most. People donate the AI tokens they won’t use, and their agents build reviewed kits for food pantries, shelters, hotlines and small nonprofits. Every kit is a noun; every step is a verb with a receipt. A kit is reviewed, not certified for any organization, and every example uses made-up data. The hosted site never calls a model; the thinking happens in volunteers’ own agents.

Example: making a video with code

ON ITS OWN

  • Falls back to basic video generation
  • Suggests old or paid tools
  • Doesn’t know motion graphics as code
  • Starts from scratch every time

CONNECTED TO THE SYSTEM

  • Shims point it to repos and benchmarks published hours ago
  • No reusable noun? The job splits into tracked verbs for a swarm
  • A link shows progress, and anyone can continue it
  • Feedback and results teach it what works

We’re producing our own demo video exactly this way.

How it works · example

Since this draft: our demo video is not made yet. The tools to make it this way are still being built, so read the last line as our plan.

Speaker notes

Someone asks their coding agent for a video built with code. On its own, the agent reaches for basic generation, old or paid tools, and doesn’t know motion graphics as code. Connected through one copied prompt, shims point it to nouns other people contributed: repos and benchmarks published hours ago. When nothing reusable exists, the job is split into tracked verbs that a swarm of workers researches and builds, with a link to follow or continue. Results and feedback teach the system which models and verbs work. Our own demo video is being made exactly this way.

Shims vs RAG

RAGShim
Where it sitsInside one app’s prompt stepBetween any agent and its model
What it addsRetrieved documentsThe right nouns: code, tools, past runs, telemetry
Can it skip the model?NoYes: answer straight from a verified noun
Can it route or check?NoPick the model, and check the response’s shape
Does it learn?RarelyEvery run becomes telemetry for the learners
Changes to the agentUsually neededNone: it’s middleware

RAG is one thing a shim can do.

Appendix · shims

Speaker notes

The question we expect: isn’t a shim just RAG? RAG retrieves documents into one app’s prompt. A shim sits between any agent and its model, as middleware, so the agent doesn’t change. It can add the right nouns like RAG does, but it can also answer from a verified noun with no model call, route to a better model, check that the response has the right shape, and record the run as telemetry for learning.

Every verb: claim, execute, report, learn

1

Claim

An agent takes one job under a lease, so two agents never collide by accident.

2

Execute

It reads the nouns the job pins and works with its own model and tools.

3

Report

It submits results, or failures, with a receipt. Checks reject wrong types and stale leases.

4

Learn

Results become new nouns, and sometimes new follow-up verbs.

Several agents can take the same brief on purpose. Each attempt keeps its own lease, output and receipt, so different solutions can be compared.

Appendix · the work loop

Speaker notes

This loop replaces babysitting. Leases stop collisions. Reports include failures, so nothing is hidden behind a final success. Every result becomes a noun the next agent can find, and a worker can add follow-up verbs, which is how a big job breaks into smaller ones.

Appendix · seed packs

Speaker notes

A seed pack is nouns plus the verbs that keep them current. A benchmark pack doesn’t just store scores; its verbs refresh them daily and test claims on our own hardware. The same pattern covers tool discovery and video as code. Visual and 3D rendering is next.

A hard test: a pack for spotting exploitation

A collection of nouns and verbs for spotting exploitation and scams hidden between ordinary-looking job posts, messages and payments, in synthetic cases.

  • Recomputes the money: fees, rates, who really gets paid
  • Checks every term against the law in force on that date
  • Tests the honest explanation too, and clears real employers
  • Never accuses; serious cases always go to a person

Evaluation: no score yet

A scored run on a frozen synthetic set was started and stopped. Answers were cut off by an 800-token limit, so nothing was scored.

It runs again only with that limit fixed and a fresh, approved budget.

Pass marks were committed before any scored run. Every case is synthetic.

Appendix · seed packs

Speaker notes

This is the hardest test of the idea. Spotting exploitation needs many sources, reusable checks like statute cards and arithmetic, and a long investigation that never accuses anyone. It is a seed pack: nouns and verbs any worker can use, not a separate product. Its scored evaluation produced no score because answers were cut off, and we say so.

It keeps learning after launch

MEMORY

Finds similar past work

Every report is fingerprinted, so an agent sees what worked before it starts.

ROUTING WEIGHTS

Picks what works

It learns which wording, shim, model and agent succeed for each kind of job.

MODEL WEIGHTS

Tunes Meta models

Small open Meta models retrain on verified results, and replace the base only when they beat it.

Feedback is a noun too. People rate results; learners use those ratings to guide future work, but never promote anything on ratings alone.

Appendix · learning

Since this draft: the first tuning rounds are measured (slide 18). With 63 examples the gain was too small to promote under the rule we set in advance; with 511 examples a fresh test comes next.

Speaker notes

Learning is split into separate, swappable learners. Memory finds similar past work from fingerprints. Routing weights learn which approach succeeds. Small open Meta models retrain on verified results in a loop that starts with very little data, and replace the base only when they beat it on a test they never saw. People’s feedback is stored as nouns that learners can use, without ever auto-promoting anything.

Appendix · built with Meta

Speaker notes

Meta’s models do the reasoning inside workers, and Meta’s open models are what the system learns into. We list only tools that are actually used; anything not yet used is marked planned. The Glimmer result is on synthetic tool-call data, and the same test set served two training runs, so it counts only after a fresh test. With 63 examples the gain was too small to trust; with 511 it was clear. More checked data mattered more than anything else.

What we don’t claim (yet)

  • Every case and workload is synthetic; results describe our test sets, not the world.
  • Passing runs show these agents and versions worked, not that every agent will.
  • The process for adding and rolling back shim rules isn’t finished.
  • Tool discovery and benchmark refresh run on demand today; daily runs come next.
  • Learning results count only when they beat the unchanged model on unseen tests.

The exploitation pack never accuses anyone. Serious cases always go to a person.

Speaker notes

We keep every failure on the record, and unknowns stay unknown. These are the boundaries of what the evidence shows today.

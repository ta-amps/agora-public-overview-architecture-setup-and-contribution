AI is smart.
The way we use it is frustratingly dumb.

A shared engine where any AI agent can find what’s new, reuse what exists, finish long jobs and keep learning.

ta-amps · github.com/ta-amps

AI models are remarkably capable. But the way we use them wastes most of that: they don’t know what came out today, they rewrite code that already exists, and they need babysitting on long jobs. Training alone doesn’t fix any of it. This project is about using AI smartly.

Why AI work is frustratingly dumb

01

It doesn’t know what’s new

New repos, tools and benchmarks appear every hour. A model can’t know what shipped after it was trained.

02

It rewrites what already exists

A model is compressed knowledge, not a library of reusable code. So it writes non-novel code again and again.

03

It needs babysitting

Big jobs are hard to break down and track. Harnesses help, but one process doing everything still loses the thread.

ACROSS ALL THREE

Training doesn’t fix it

New models help at the edges, but no model can know what shipped after its release, keep a library of reusable code, or run a project’s queue by itself.

The problem

Three problems. Models don’t know what shipped an hour ago. A model is compressed knowledge, not a code library, so it regenerates code that already exists. And it can’t carry a long, multi-step project without a person watching; harnesses help, but a single process trying to do everything still loses track. Underneath all three: training doesn’t fix it. Newer models help a little, but no model can know what was released after it was trained.

Why it keeps happening

Models aren’t trained to organize, reuse or learn from their own work.

Harnesses each try, in their own way. So in practice, AI work is rarely organized, reused or learned from, and there’s no standard way to do it.

The problem

The model itself isn’t trained to organize, reuse or learn from what it produces. Some harnesses add pieces of that, each differently, so there’s a hodgepodge of partial solutions and no shared standard. That’s the gap we fill.

One answer, three parts

PART 1

Nouns and verbs

Nouns are reusable things: tools, code, results, even past runs and telemetry. Verbs are small jobs any agent can claim, execute and report.

PART 2

Shims

Put the right nouns in front of any agent as it works, or answer with no model call at all.

PART 3

Learning

Every report improves what gets reused, what gets shown, and which models and verbs work best.

Workers don’t just use nouns and verbs. They create both: new findings, and new follow-up jobs.

One shared engine, Tessera, keeps the queue, the results and the permissions.

The answer

Three parts. Nouns and verbs give AI work a shared shape: reusable things, and small jobs that are claimed, executed and reported, including failures. Shims deliver the right nouns, including past runs and telemetry, to any agent without changing it. Learning means every report makes the next job better. And workers can create new verbs, not just nouns, which is how big jobs break down into smaller ones.

How it works · example

Someone asks their coding agent for a video built with code. On its own, the agent reaches for basic generation, old or paid tools, and doesn’t know motion graphics as code. Connected through one copied prompt, shims point it to nouns other people contributed: repos and benchmarks published hours ago. When nothing reusable exists, the job is split into tracked verbs that a swarm of workers researches and builds, with a link to follow or continue. Results and feedback teach the system which models and verbs work. Our own demo video is being made exactly this way.

RAG is one thing a shim can do.

Appendix · shims

The question we expect: isn’t a shim just RAG? RAG retrieves documents into one app’s prompt. A shim sits between any agent and its model, as middleware, so the agent doesn’t change. It can add the right nouns like RAG does, but it can also answer from a verified noun with no model call, route to a better model, check that the response has the right shape, and record the run as telemetry for learning.

Every verb: claim, execute, report, learn

1

Claim

An agent takes one job under a lease, so two agents never collide by accident.

2

Execute

It reads the nouns the job pins and works with its own model and tools.

3

Report

It submits results, or failures, with a receipt. Checks reject wrong types and stale leases.

4

Learn

Results become new nouns, and sometimes new follow-up verbs.

Several agents can take the same brief on purpose. Each attempt keeps its own lease, output and receipt, so different solutions can be compared.

Appendix · the work loop

This loop replaces babysitting. Leases stop collisions. Reports include failures, so nothing is hidden behind a final success. Every result becomes a noun the next agent can find, and a worker can add follow-up verbs, which is how a big job breaks into smaller ones.

Feedback is a noun too. People rate results; learners use those ratings to guide future work, but never promote anything on ratings alone.

Appendix · learning

Learning is split into separate, swappable learners. Memory finds similar past work from fingerprints. Routing weights learn which approach succeeds. Small open Meta models retrain on verified results in a loop that starts with very little data, and replace the base only when they beat it on a test they never saw. People’s feedback is stored as nouns that learners can use, without ever auto-promoting anything.

What we don’t claim (yet)

  • Every case and workload is synthetic; results describe our test sets, not the world.
  • Passing runs show these agents and versions worked, not that every agent will.
  • The process for adding and rolling back shim rules isn’t finished.
  • Tool discovery and benchmark refresh run on demand today; daily runs come next.
  • Learning results count only when they beat the unchanged model on unseen tests.

Shamash never accuses anyone. Serious cases always go to a person.

Appendix · honest limits

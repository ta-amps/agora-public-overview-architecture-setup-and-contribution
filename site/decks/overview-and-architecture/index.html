Overview and architecture

AI is smart.
The way we use it is frustratingly dumb.

Everything is nouns and verbs: verbs are tasks, and nouns are everything a task uses or makes. On one shared engine, any AI agent can find what’s new, reuse what exists, finish long jobs and re-tune on demand.

ta-amps · Overview and architecture · ta-amps · Agora, the overview · October 30, 20261

Speaker notes

AI models are remarkably capable, but the way we use them wastes most of that. They don’t know what came out today, they rewrite code that already exists, and they need babysitting on long jobs. This deck shows the fix: everything is a noun or a verb, where verbs are tasks and nouns are everything a task uses or makes, on one shared engine whose learners read its reports; we re-tune on demand and promote only after evaluation.

Why AI work is frustratingly dumb

01

It doesn’t know what’s new, and neither do we

New repos, papers and tools appear every day, faster than any model or any person can follow.

02

It rewrites what already exists

A model is compressed knowledge, not a library of reusable code. So it writes the same code again and again.

03

It needs babysitting

It doesn’t break a big job into small, independent pieces that many workers can claim, check and finish.

ACROSS ALL THREE

Training alone doesn’t fix it

New models help at the edges, but no model knows what shipped after its release, keeps a library of reusable code, or runs a long job’s queue by itself.

ta-amps · Overview and architecture · The problem2

Speaker notes

Three problems. First, nobody can keep up: new repos, papers and tools land every day, models can’t know what shipped after training, and people can’t read it all either. Second, a model is compressed knowledge, not a code library, so it regenerates code that already exists. Third, it doesn’t break a big job into small, independent pieces that many workers can claim, check and finish; harnesses help, but one process trying to do everything still loses track. Underneath all three, training alone doesn’t fix it.

Speaker notes

Everything is one of two things, in plain words: verbs are tasks, and nouns are everything a task uses or makes. This is not a model architecture, and it isn’t a new kind of model: it’s how the work is organized, so any agent on any model can take part. Empirical benchmarks across coding harnesses and persona studies show expert role-play lines add zero factual accuracy while irrelevant or demographic persona fluff degrades agent performance by 26 to 30 percent and instructions drift within eight turns -- which is why ta-amps separates routing descriptions from permissions (hierarchy routes, it never authorizes) and puts precision into Task Objects, output contracts, scoped tool limits and context shims. Nouns are things like context, reusable pieces of code in containers, the skills, tools and hooks a harness loads, an agent’s whole setup with its harness, model and files, run logs, past runs, datasets and links to trending repos. Each one is described by metadata, so any agent, harness, bot or worker with the right permissions can search for it and use it, and nouns that link to other nouns can describe a whole system, such as a pipeline or a team of agents. A verb is an atomic instruction, the smallest reasonable task, which a worker claims, does and reports; a worker that needs help adds more verbs, and what each one makes is kept as nouns. Surfaces are only the ways in, and infrastructure only keeps it safe and on the record. Instructions, page text and settings are nouns too, and contributing is a verb.

Speaker notes

Each problem has a direct answer. Feeds fix the first: feed verbs keep each new item as a noun with its source and date. A daily check watches our own live services every day, and the packs hold the verbs for new repos, papers and model releases. Search and retrieval fix the second: when an agent starts working, the tested code, past runs and rules it needs are found and put in front of its model by Herma, or Herma answers directly with no model call, so the agent reuses instead of rewriting. A shared queue fixes the third: the agent holding a big job splits it into small verbs that many workers claim, check and finish, each leased and receipted, so nobody has to babysit. And because training alone doesn’t fix any of this, small open models are tuned in a loop, and a tuned model replaces its base only if it beats it on a test it never saw. So far the training rows come from templates, not from work reports or provider outputs, and the tests are example; learning from real work reports is next. The measured results are on the learning slide.

Seed packs bundle nouns and verbs

A seed pack is a plain-named collection of nouns and verbs for one kind of work. Reading or importing one runs nothing and grants nothing.

  • 80 packs live in one library, each named for what it does.
  • Tested code can ship inside a pack, as nouns, with its own tests.
  • Any agent can generate a pack and submit it for review.
  • The use case: on Eranos, a nonprofit types what it needs. The first step sorts it: an agent kit for the parts that touch private files, and work by donated agents for the parts that public information can answer.

AN AGENT KIT IS A SEED PACK

Nouns and verbs for one organization’s agent

Nouns: instructions, skills, knowledge, connections, settings, working files, checks and tests

Verbs: a step map of what the agent drafts and what only a person does, plus building, testing and reviewing the kit

One noun can hold an agent’s whole setup: its harness, its model and the files in its working folder.

Speaker notes

A seed pack is just nouns and verbs with a plain name, such as composing verified code without rewriting it, or video and motion made with code. Packs are never surfaces and carry no brand. Importing one doesn’t run, activate or admit anything, and it never copies credentials. An agent kit is the same thing made for one organization’s agent, and the agent that builds a kit can never approve it.

Speaker notes

This is the map. Nouns and verbs are the largest pieces, at the top, because they are the system. Seed packs bundle them under plain names, and an agent kit is a seed pack made for an NGO’s agent. People and agents use and create them through two public surfaces: Eranos, the two-sided marketplace, and Agora, this overview. Everything runs on two pieces of infrastructure that nobody visits: Tessera keeps the work and the records, and Herma connects any agent to context and models.

Tessera, the work and storage engine

Every verb is a tile: leased to one worker at a time, claimed once, finished once, and handed back with a receipt.

LEASES

One worker per verb

Every claim raises a fencing token, so a stalled worker’s late write is refused.

RECEIPTS

A receipt for every result

A submit stores the result once and returns a SHA-256 of exactly what was written. A retry gets the first receipt back.

COMPARE-AND-SET NOUNS

No version is lost

Every write names the version it read, so nothing is silently overwritten, and every version stays readable.

PERMISSIONS

Scoped to its own queues

Each key reaches only the queues it was issued for. Deploying, publishing and paying stay with a person.

LEARNERS

Built to learn from reports

Swappable learners read execution reports: similar past work and what succeeds.

HOW AGENTS CONNECT

Any agent, any harness

MCP at /mcp, HTTP under /v1/, plain web forms at /work, and a board for people at /board.

ta-amps · Overview and architecture · How the pieces fit · Tessera, infrastructure9

Speaker notes

Tessera is the shared engine. Leases stop two agents grabbing the same verb, and fencing tokens stop a stalled agent from overwriting whoever took over. Every result comes back with a receipt, and a retried submit gets the first receipt instead of a second copy. Nouns change only by compare-and-set and keep every version. Keys reach only their own queues, and anything public, such as deploying, publishing or paying, stays with a person. Learners are separate pieces that read execution reports; they are infrastructure plumbing, not a hidden agent. Model tuning’s training rows come from templates.

Herma, the shim

It sits between any agent’s harness and its model, and adds nouns as context or answers directly.

RAG is one thing a shim can do. The agent itself doesn’t change.

ta-amps · Overview and architecture · How the pieces fit · Herma, infrastructure10

Speaker notes

Herma is middleware between a harness and its model. When a request matches a rule, it adds the right nouns as context, or, when a verified noun already answers, it replies directly with no model call. RAG retrieves documents into one app’s prompt; a shim can do that and more, and the agent doesn’t change. Today configured shim rules work, including direct answers; the process for adding, switching on and rolling back rules isn’t finished.

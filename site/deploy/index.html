Run any slice yourself

You don’t have to adopt the whole stack at once. Start with seed packs, ready-made sets of Tasks, inside an agent you already use, run your own Teleion Fabric and its model shim on Cloudflare, try the whole loop offline in Docker, or fine-tune Muse Glimmer 30B adapters on your own GPUs.

1. Choose only the slice you need

Every part speaks plain HTTP JSON and JSON-RPC 2.0 MCP, so each one can run on Cloudflare, in a Linux container or on your own machine without changing an agent’s prompts.

  • No server

    Slice A: seed packs only, inside the agent you use

    Take any seed pack’s Task Objects, Task templates and standard-library Python checks straight into the coding agent you already use.

    Best when you want reusable schemas, deterministic checks or nonprofit agent kits without hosting anything.

    # Clone the seed-pack library (its address is on Agora's Library page), then, in the clone:
python3 scripts/validate_packs.py
# Run one pack's own checks (standard-library Python, no keys):
make -C packs/frame-by-frame-video-qa/code check

  • Cloudflare Workers

    Slice B: your own Teleion Fabric and its model shim on Cloudflare

    Run your own queue and Task Object store (Teleion Fabric) and your own shim (Teleion Fabric's model shim) on Cloudflare, with the commands each repository gives.

    Best for teams, labs or nonprofits that want an always-on HTTPS and MCP endpoint, where only one worker holds a Task at a time and no write overwrites a newer one.

    # 1. Sign in to your Cloudflare account
npx wrangler login

# Your account needs its own D1 databases: create each one that deploy/cloudflare/wrangler.jsonc names
# (npx wrangler d1 create <name>) and put its id in that file before you deploy.

# 2. Teleion Fabric: the queue, the Task Object stores and the /mcp endpoint
git clone https://github.com/ta-amps/teleion-fabric-infrastructure-work-and-storage-engine.git
cd tessera-infrastructure-work-and-storage-engine
npx --yes wrangler@4.154.0 secret put BOOTSTRAP_SECRET --config deploy/cloudflare/wrangler.jsonc
npx --yes wrangler@4.154.0 deploy --config deploy/cloudflare/wrangler.jsonc

# 3. Teleion Fabric's model shim: the shim, with its own D1 database
cd ..
git clone https://github.com/ta-amps/herma-infrastructure-shim-for-intelligent-agents.git
cd herma-infrastructure-shim-for-intelligent-agents
npx --yes wrangler@4.149.0 d1 execute ta-amps-herma --remote --file deploy/cloudflare/d1-herma.sql --config deploy/cloudflare/wrangler.jsonc -y
npx --yes wrangler@4.149.0 deploy --config deploy/cloudflare/wrangler.jsonc
npx --yes wrangler@4.149.0 secret put BOOTSTRAP_SECRET --config deploy/cloudflare/wrangler.jsonc

  • Docker

    Slice C: the whole loop offline, in Docker

    Run Teleion Fabric locally, check the starter seed pack, and run a two-worker test of claiming a Task and an independent review, with no keys and no outside network.

    Best for offline demos, internal CI or strict data residency.

    git clone https://github.com/ta-amps/ta-amps-hackathon.git
cd ta-amps-hackathon
docker compose up --build --abort-on-container-exit --exit-code-from sample-worker-smoke

  • Your own GPUs

    Slice D: fine-tune Muse Glimmer 30B, Meta’s open-weight model

    Start from the QLoRA adapter settings ta-amps used to fine-tune Muse Glimmer 30B on two free Kaggle T4 GPUs, and the Python packages a GPU worker needs.

    Best when you want to tune your own adapters from your own recorded, reviewed task results.

    git clone https://github.com/ta-amps/ta-amps-hackathon.git
cd ta-amps-hackathon
# The adapter settings ta-amps used for Muse Glimmer 30B:
cat training/adapters/glimmer-30b-qlora/adapter_config.json
# The packages a GPU worker needs (install them only inside a GPU worker):
pip install -r training/requirements-train.txt

A task doesn’t care where it runs. These cards say what each partner would do in the system and what has actually run there. Each card’s state comes from the partner compute record.

  • Modal

    serverless GPUs

    Checked offline

3. Run the two public sites, Agora and Eranos

The sites hold no admin keys. You can host Agora on any static host, and Eranos on its own Cloudflare Worker.

  • Agora, the static overview

    Agora is built from the JSON in site/content/ by standard-library Python, with no npm at run time. Serve the site/ folder from Cloudflare Pages, Workers static assets or any web server.

    # Agora's source: https://github.com/ta-amps/agora-public-overview-architecture-setup-and-contribution
# In its folder, check that every page is built from its source:
python3 scripts/build_site.py --check

# Option 1: deploy the site/ folder to Cloudflare Pages
npx wrangler pages deploy site --project-name=agora-hub

# Option 2: serve it with Docker on port 8080
docker build -t ta-amps-agora . && docker run --rm -p 8080:8080 ta-amps-agora

  • Eranos, the marketplace (a Cloudflare Worker with D1 and a scoped Teleion Fabric key)

    Eranos reads and writes Teleion Fabric with a scoped surface key, so visitors can browse reviewed kits and follow requests without touching any admin store.

    git clone https://github.com/ta-amps/eranos-public-marketplace-for-public-good-token-burn.git
cd eranos-public-marketplace-for-public-good-token-burn
make check

# The surface key for your own Teleion Fabric (never an admin key):
npx wrangler secret put TESSERA_SURFACE_KEY --config deploy/cloudflare/wrangler.jsonc
pnpm --dir web install --frozen-lockfile && pnpm --dir web build
npx --yes wrangler@4.149.0 deploy --config deploy/cloudflare/wrangler.jsonc

4. A security checklist for your own copy

Keep these four boundaries whenever you run your own copy, on Cloudflare or in containers.

  • Surface keys and worker keys

    Give web surfaces a read and submit surface key, and give each worker a narrow key scoped to its queues. Never put an admin key in a browser or in a surface’s code.

  • Compare-and-set writes

    Create a new Task Object with expected_version 0 and update one with its exact version, so concurrent workers get HTTP 409 Conflict instead of overwriting each other.

  • Short-lived sessions for public demos

    When signed-out visitors try live flows, such as the Live Studio, give them a short-lived anonymous session in its own namespace, with a per-address rate limit.

  • Probes after every deploy

    Check /v1/health, JSON-RPC tools/list on /mcp and a surface readback before sending traffic or workers to a new deployment.
